# Концепция интерфейса: полка формуляров и папок с паспортами

**Связь с ТЗ:** дополняет `tz-etap-a-minimal.md` (этап A — титулы) и задаёт целевой UX для полного контура.  
**Принцип:** визуал и навигация повторяют реальный порядок работы техника: *полка → формуляр самолёта → разжимная папка → паспорт (листание страниц)*.

---

## 1. Главная идея

Интерфейс — не «таблица БД» и не дашборд, а **рабочая библиотека цеха**:

| Реальный объект | Объект в UI | Как выглядит |
|-----------------|-------------|--------------|
| Полка / стеллаж | Домашний экран | Ряды корешков книг и папок |
| Формуляр самолёта | «Книга» формуляра | Толстый корешок с бортовым номером |
| Разжимная папка с паспортами | «Папка» | Корешок/титульник с номером папки и списком агрегатов |
| Паспорт агрегата | «Книга» паспорта | Тонкий том; страницы листаются как в книге |
| Связь формуляр ↔ паспорт | Перекрёстные ссылки | Клик по строке формуляра → паспорт; из паспорта → строка формуляра и папка |

Техник ищет документ **так же, как руками**: по борту, по номеру папки, по наименованию/зав. № — и видит привычные корешки, а не абстрактные «карточки CRM».

---

## 2. Информационная структура (три уровня)

```
Полка
 ├── Книга: Формуляр ВС (борт …)
 │     └── строки учёта агрегатов
 ├── Папка № N (разжимная)
 │     └── список паспортов внутри
 └── Книга: Паспорт агрегата
       ├── стр. 1 — титул (ГОСТ-раскладка)
       ├── стр. 2 — ресурсы / сроки / приёмка ВП   ← после этапа A
       └── стр. 3 — установка на борт / снятие / наработка  ← после этапа A
```

### 2.1. Формуляр самолёта

Экран раскрытой книги формуляра. Содержание строк (минимум):

| Поле | Назначение |
|------|------------|
| Наименование агрегата | как в паспорте / формуляре |
| Порядковый номер в формуляре | внутренняя нумерация учёта |
| Зона обслуживания / место установки | привязка к борту (можно заполнять позже) |
| Дата установки | связь с экземпляром на борту |
| Заводской номер | ключ к паспорту |
| № разжимной папки | где лежит бумажный/цифровой паспорт |

**Связь:** `наименование + заводской номер + дата установки` → конкретный паспорт (и обратно).

Клик по строке:

1. подсветка связанного паспорта;
2. переход «Открыть паспорт»;
3. дополнительно: «Открыть папку № N».

### 2.2. Разжимная папка

Отдельный объект библиотеки (не страница формуляра).

- **Корешок на полке:** `Папка № …` + кратко 2–4 имени агрегатов (или «и ещё N»).
- **Титульник / разворот папки:** полный перечень хранящихся паспортов (наименование, зав. №, ссылка на формуляр/борт).
- Внутренняя нумерация папки сохраняется как у техника в цехе (поле `folder_number` + опционально `slot_in_folder`).

Папка — **навигационный контейнер**, как в реальности: «где лежит бумага».

### 2.3. Паспорт (многостраничная книга)

Раскладка титула — **по ГОСТу** (как в ТЗ этапа A). Дальше — листание:

| Страница | Содержание | Этап |
|----------|------------|------|
| 1. Титул | наименование, шифр, обозначение, №, год, корешок, ОКП/ФНН… | A (сейчас) |
| 2. Ресурсы и сроки | назначенный/межремонтный ресурс, срок службы, отметки приёмки военного представительства | B+ |
| 3. Учёт на борту | номер ВС, даты установки/снятия, наработка | B+ |

Листание: стрелки, клик по обрезу страниц, жесты на планшете; анимация переворота **сдержанная** (1 движение, без «листалки ради эффекта»). Нумерация страниц и миниатюры обрезов справа/снизу — как у реальной книги.

На каждой странице паспорта — постоянная зона связей:

- «В формуляре борта …» (строка);
- «Папка № …»;
- при нескольких установках в истории — список событий с датами.

## 3. Домашний экран: полка

### 3.1. Композиция

Один основной вид — **полка**:

- слева/сверху фильтры: борт, № папки, поиск по зав. № / наименованию;
- центр — полки с корешками;
- без сетки «карточек-плиток» как в админке: корешок = основной объект выбора.

Два типа корешков визуально различимы:

| Тип | Визуальный язык |
|-----|-----------------|
| Формуляр | «книжный» корешок, бортовой номер крупно, тип ВС мельче |
| Папка | «картон/файловая» фактура, номер папки крупно, список имён мелко |

Паспорта **на полке по умолчанию не свалены россыпью** — они живут **внутри папок** (как в цехе). Отдельный том паспорта открывается из папки или из строки формуляра. Поиск по зав. № может сразу открыть паспорт, но в «хлебных крошках» видно: `Полка → Папка №12 → Паспорт …`.

### 3.2. Поиск «как у техника»

Строка поиска понимает:

- борт (`RA-…` / бортовой номер);
- `папка 12` / `№12`;
- заводской номер;
- наименование / шифр (МГВ, ППК-У…).

Выдача подсвечивает нужный корешок на полке и/или строку внутри формуляра.

---

## 4. Навигация формуляр ↔ паспорт ↔ папка

Обязательные переходы (без тупиков):

```
Формуляр (строка) ⇄ Паспорт
Формуляр (строка) → Папка № N → Паспорт
Паспорт → Формуляр (нужная строка)
Паспорт → Папка № N
Папка → Паспорт → Формуляр
```

В шапке раскрытого документа — «тропа»:

`Полка / Борт 12345 / Формуляр → строка 07 → Папка 12 → Паспорт МГВ-1СУ8 №1160340`

Кнопка «Назад к полке» всегда доступна.

## 5. Загрузка и распознавание в этом UI

Не отдельный «экран OCR», а действие **внутри** книги/папки:

1. Техник открыл папку или создаёт паспорт в папке.  
2. «Добавить / обновить страницу с фото».  
3. Фото кладётся на нужную страницу книги (титул — стр. 1).  
4. Распознавание заполняет поля; расхождения подсвечиваются на **том же развороте**, что и бумажный аналог.  
5. Подтверждение оператора = «подписать карандашом» в цифровом смысле (без имитации печати обязательно).

Так сохраняется ощущение: *работаю с документом*, а не *заполняю веб-форму*.

## 6. Визуальный стиль (чтобы «не отличался от реальности»)

Ориентиры:

- спокойная «бумажная» палитра (бумага формуляра, картон папки, тёмные корешки) — **не** неон, не фиолетовый SaaS-градиент, не стекломорфизм;
- типографика с характером канцелярии/техдокументации (читаемая антиква/гротеск для UI-хрома + более «бланковая» для полей титула);
- лёгкая фактура бумаги/картона на разворотах, но без шума, мешающего чтению;
- ГОСТ-титул — максимально близко к бумажному образцу (как в ТЗ);
- анимации: выдвижение книги с полки, раскрытие, перелист страницы — 2–3 осмысленных движения, без декоративной мишуры;
- на мобильном/планшете техника — крупные корешки и зоны нажатия, поиск сверху.

**Не делать:** плотную «админку» из таблиц на первом экране; карточки со статистикой в герое; бейджи поверх разворота паспорта.

Таблицы допустимы **внутри** формуляра — там они и в реальности табличные.

## 7. Что входит в этап A vs позже

| Элемент UI | Этап A (CPU MVP) | Далее |
|------------|------------------|-------|
| Полка с формуляром и папками | упрощённо: 1 борт, папки, паспорта | много бортов |
| Формуляр: строки + № папки + зав. № | да (можно без зон) | зоны обслуживания |
| Папка: титульник со списком | да | внутренняя нумерация слотов |
| Паспорт: страница 1 (титул ГОСТ) | да | — |
| Листание стр. 2–3 | заготовка «скоро» / пустые листы-заглушки | полное содержание |
| Переходы формуляр ↔ паспорт ↔ папка | да | история установок |
| Фото → OCR на титул | да | фото на все страницы |

На этапе A уже закладывается **модель книги** (страницы 2–3 могут быть недоступны для редактирования, но обрезы страниц видны — техник понимает структуру наперёд).

---

## 8. Ключевые экраны (карта)

1. **Полка** — выбор формуляра / папки.  
2. **Формуляр (разворот)** — таблица агрегатов борта.  
3. **Папка (титульник)** — оглавление паспортов.  
4. **Паспорт (книга)** — листаемые страницы; титул по ГОСТу.  
5. **Сравнение/diff** — при повторном фото (модернизация) на том же развороте.  
6. **Журнал** — доступ из паспорта/формуляра, оформлен как «вкладыш/реестр», не как чужой модуль.

---

## 9. Критерий «интерфейс удался»

Техник без обучения на «IT-систему» может:

1. найти борт на полке;  
2. в формуляре увидеть, в какой папке паспорт;  
3. открыть папку и паспорт;  
4. вернуться в строку формуляра одним действием;  
5. на этапе A обновить титул с фото и понять, куда потом лягут листы ресурса и установки.

Если убрать подписи «меню / модули» и останутся только полка, корешки и развороты — сценарий всё равно считывается: значит, метафора работает.

## 10. Связь с данными (кратко)

| UI-объект | Ключевые поля |
|-----------|---------------|
| Формуляр | `aircraft_id`, строки: `name`, `line_no`, `zone`, `installed_at`, `serial_number`, `folder_no` |
| Папка | `folder_no`, список `component_id` / оглавление |
| Паспорт | `serial_number`, `name`/`cipher`, страницы 1..n, связь с строкой формуляра через `serial_number` + `installed_at` (+ `aircraft_id`) |

Именно эта связка обеспечивает свободный переход «туда-обратно», который вы описали.
