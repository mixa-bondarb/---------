# Техническое задание

## на разработку программы имитационного моделирования жизненного цикла парка воздушных судов с визуализацией в среде электронных таблиц

**Программа:** «KAJC»  
**Документ:** Техническое задание  
**Формат результата моделирования:** Microsoft Excel (`.xlsx`)

---

## 1. Общие сведения

### 1.1. Наименование программы

Полное наименование: программа имитационного моделирования жизненного цикла парка воздушных судов с визуализацией в среде электронных таблиц.

Краткое наименование: **«KAJC»** (далее — Программа).

### 1.2. Основание для разработки

Основанием для разработки является потребность в инструменте прогнозирования технического состояния парка воздушных судов (ВС) с учётом:

- ограниченных производственных (ремонтных) мощностей;
- логики планирования ремонтов;
- календарного срока службы и межремонтного срока службы;
- очерёдности обслуживания (FIFO).

### 1.3. Назначение документа

Настоящее Техническое задание определяет цели, функциональные и нефункциональные требования, состав входных и выходных данных, правила перехода состояний, требования к визуализации, интерфейсу, надёжности и документированию Программы.

---

## 2. Назначение и цели создания программы

### 2.1. Назначение

Программа предназначена для имитационного моделирования жизненного цикла совокупности воздушных судов во времени с шагом **один календарный год** и визуализации динамики состояний каждого ВС на листе электронной таблицы Microsoft Excel.

Модель строится по метафоре популяции в клеточном автомате (игра «Жизнь»), где:

- отдельные объекты (ВС) подчиняются единым правилам;
- объекты взаимодействуют через общий ограниченный ресурс — мощности по ремонту;
- объекты переходят из одного состояния в другое под влиянием:
  - истечения календарного срока службы;
  - истечения межремонтного срока службы;
  - очерёдности обслуживания.

### 2.2. Цели разработки

1. Прогноз занятости ремонтных мощностей.
2. Выявление накопления очереди на ремонт.
3. Определение моментов списания ВС по окончании срока службы.
4. Наглядное представление «популяции» ВС в виде цветовой матрицы, где цвет ячейки соответствует состоянию конкретного самолёта в конкретном году.

## 3. Требования к программе

### 3.1. Функциональные требования

#### 3.1.1. Импорт исходных данных

Программа должна считывать исходные параметры из файла формата `.xlsx`.

Расположение и наименования столбцов входного листа строго регламентированы (см. п. 3.2).

#### 3.1.2. Параметры моделирования

Пользователем задаются следующие параметры:

| Параметр | Единица / формат | Описание |
|---|---|---|
| Дата начала моделирования | год (ГГГГ) | Первый год горизонта моделирования |
| Продолжительность моделирования | число лет | Длина горизонта моделирования |
| Количество ремонтных мест | целое число ≥ 0 | Мощность ремонтного завода (параллельных слотов) |
| Длительность одного ремонта | лет | Единая для всех типов ремонта |
| Назначенный срок службы ВС | лет | Глобальная константа (если не задана индивидуально) |
| Межремонтный срок службы | лет | Глобальная константа (если не задана индивидуально) |

#### 3.1.3. Расчёт и актуализация срока службы

В процессе моделирования:

1. Фактический календарный возраст каждого ВС увеличивается с истечением времени (по годовым шагам).
2. Межремонтный счётчик (календарный интервал с момента последнего ремонта или с начала эксплуатации) увеличивается по годовым шагам, пока ВС находится в эксплуатации или в очереди.
3. При выходе из ремонта межремонтный ресурс восстанавливается полностью: межремонтный счётчик обнуляется, отсчёт межремонтного цикла начинается заново.

#### 3.1.4. Правила перехода между состояниями («правила жизни популяции»)

Каждый экземпляр ВС может находиться в одном из четырёх состояний:

| Код | Состояние | Краткое обозначение |
|---|---|---|
| 1 | Эксплуатация | Э |
| 2 | Ожидание ремонта (простой в очереди) | Ож |
| 3 | Ремонт | Р |
| 4 | Списание | С |

Переходы осуществляются ежегодно по следующим логическим условиям.

**Из Э в Ож / Р**

Если календарный интервал с момента последнего ремонта достиг межремонтного срока службы **ИЛИ** с начала эксплуатации ВС требует ремонта (межремонтный порог достигнут):

- при наличии свободного ремонтного места ВС немедленно переходит в состояние **Р**;
- при отсутствии свободного места ВС становится в очередь (состояние **Ож**).

**Из Ож в Р**

Как только освобождается ремонтное место, первый ВС в очереди (принцип **FIFO**) переходит в состояние **Р**.

**Из Р в Э**

По истечении заданной длительности ремонта ВС возвращается в эксплуатацию с обнулённым межремонтным счётчиком (календарный срок в межремонтном цикле начинает отсчитываться заново).

**Переход в С (списание / «смерть»)**

Если в любом состоянии, кроме уже наступившего списания, выполняется условие:

- календарный возраст ВС (от даты выпуска) достиг назначенного срока службы,

то ВС немедленно переходит в состояние **Списание** и исключается из дальнейших расчётов:

- не занимает ремонтное место;
- не возвращается в эксплуатацию;
- не участвует в очереди.

#### 3.1.5. Визуализация в Excel

Программа формирует выходной файл `.xlsx`, содержащий лист с матрицей «ВС × Годы».

Каждая ячейка закрашивается в соответствии с состоянием ВС в данный год (см. п. 3.4).

### 3.2. Требования к входным данным

Входной файл Excel должен содержать лист с именем **`Исходные_данные`** и следующие обязательные столбцы (названия строго соответствуют указанным):

| Имя столбца | Тип данных | Описание |
|---|---|---|
| Заводской номер | строка / число | Уникальный идентификатор экземпляра ВС |
| Бортовой номер | строка | Бортовой номер ВС |
| Дата выпуска | дата / год | Дата (год) выпуска ВС |
| Дата последнего ремонта | дата / год | Дата последнего ремонта; если отсутствует — отсчёт ведётся с даты выпуска |

**Примечание.** Если индивидуальные значения назначенного срока службы и/или межремонтного срока службы не заданы, используются глобальные параметры из п. 3.1.2.

Допускается расширение входной таблицы необязательными столбцами (например, индивидуальный назначенный срок службы, индивидуальный межремонтный срок), при условии сохранения обязательных столбцов и их имён.

### 3.3. Требования к выходным данным

Результирующий файл Excel должен содержать следующие листы.

#### 3.3.1. Лист `Результаты`

Таблица, где:

- **строки** соответствуют экземплярам ВС (идентификация по заводскому и/или бортовому номеру);
- **столбцы** соответствуют календарным годам моделирования (подпись года в формате `ГГГГ`);
- **крайний правый столбец** — «Год списания» (заполняется номером года списания; при отсутствии списания в горизонте моделирования — пусто или специальная пометка «не списан»).

Ячейки матрицы содержат код/краткое обозначение состояния и/или окрашиваются согласно п. 3.4.

#### 3.3.2. Лист `Параметры`

Перечень настроек, использованных при расчёте, для обеспечения воспроизводимости:

- путь/имя исходного файла;
- год начала моделирования;
- продолжительность моделирования (лет);
- количество ремонтных мест;
- длительность ремонта (лет);
- глобальный назначенный срок службы (лет);
- глобальный межремонтный срок службы (лет);
- дата/время выполнения расчёта (рекомендуется);
- версия Программы (рекомендуется).

### 3.4. Требования к цветовой индикации

Закраска ячеек должна выполняться встроенными средствами Excel (заливка) и строго соответствовать состояниям:

| Состояние | Цвет заливки | Примечание |
|---|---|---|
| Эксплуатация (Э) | Зелёный | ВС находится в строю |
| Ремонт (Р) | Жёлтый | ВС находится на ремонтном месте |
| Ожидание ремонта (Ож) | Голубой | ВС простаивает в ожидании освобождения места |
| Списание (С) | Красный | Год наступления списания и все последующие годы до конца горизонта моделирования остаются красными |

**Особые случаи:**

- Ячейки **до начала «жизни» ВС** (если моделирование начинается позже даты выпуска — не применяется; если дата выпуска позже начала моделирования) должны оставаться **незакрашенными** с пометкой в примечании (комментарии Excel), например: «ВС ещё не введён в эксплуатацию».
- После списания все последующие ячейки строки остаются красными до конца горизонта.

Рекомендуемые RGB-значения (допускается уточнение при реализации при сохранении смысловой палитры):

| Состояние | Рекомендуемый цвет |
|---|---|
| Эксплуатация | `#70AD47` (зелёный) |
| Ремонт | `#FFC000` (жёлтый) |
| Ожидание ремонта | `#5B9BD5` (голубой) |
| Списание | `#FF5050` (красный) |

## 4. Описание алгоритма (метафора игры «Жизнь»)

### 4.1. Общая идея

Модель представляет собой клеточный автомат с дискретным временем, где каждая «клетка» (ВС) в каждом такте (годе) может изменить состояние в зависимости от:

- собственного счётчика возраста и межремонтного интервала;
- состояния среды (загрузки ремонтной мощности).

### 4.2. Правила обновления (метафора)

| Правило | Смысл в модели |
|---|---|
| 1. Рождение | Не применяется (все ВС изначально присутствуют во входных данных) |
| 2. Выживание | ВС остаётся в эксплуатации, пока не достигнут межремонтный порог и не исчерпан назначенный срок службы |
| 3. Болезнь | Необходимость ремонта при достижении межремонтных лимитов |
| 4. Лечение | Перевод в состояние «Ремонт» при наличии свободного места, иначе — в очередь |
| 5. Смерть | Безвозвратный переход при исчерпании назначенного срока службы |
| 6. Взаимодействие через среду | Доступные ремонтные места — разделяемый ресурс, распределяемый по принципу FIFO среди всех ВС в состоянии ожидания |

### 4.3. Порядок обработки на каждом годовом шаге

На каждом годовом шаге обработка состояний выполняется в **строгом порядке**:

1. Фиксируются события **списания**.
2. Обрабатываются **завершения ремонта** (освобождаются ремонтные места).
3. Перемещаются ВС из **очереди в ремонт** (FIFO, пока есть свободные места).
4. Фиксируются **новые требования к ремонту** (по календарю / межремонтному порогу).
5. Снова пополняется очередь / занимаются места, если мест недостаточно / достаточно.

### 4.4. Допущения модели

1. Дискретность времени — **1 календарный год**.
2. Длительность ремонта одинакова для всех ВС и задаётся пользователем.
3. Ремонт полностью восстанавливает межремонтный ресурс, но **не** обнуляет календарный возраст ВС.
4. Списание имеет приоритет над ремонтом и эксплуатацией.
5. Очередь общая для всего парка (единый ремонтный завод).
6. Дисциплина обслуживания — FIFO.
7. ВС, списанный в текущем году, не занимает ремонтное место в этом и последующих годах.

## 5. Требования к надёжности

1. Программа должна корректно обрабатывать граничные случаи:
   - пустой входной файл / пустой лист `Исходные_данные`;
   - отсутствие обязательных столбцов или некорректные имена столбцов;
   - отсутствие ремонтных мощностей (количество мест = 0 — все нуждающиеся ВС ожидают);
   - нулевая/некорректная продолжительность моделирования;
   - дата последнего ремонта отсутствует (отсчёт с даты выпуска);
   - дата выпуска позже начала моделирования (ячейки до ввода в строй незакрашены).
2. При возникновении ошибок выводятся информативные сообщения пользователю.
3. Целостность исходного файла не нарушается: запись выполняется только в выходной файл.
4. Рекомендуется валидация входных параметров до старта расчёта (отрицательные значения, нечисловые поля и т.п.).
