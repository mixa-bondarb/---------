Проверь технологическую карту (структура приведена ниже) на соответствие требованиям к мерам безопасности.

Принцип проверки (важно): полные формулировки мер безопасности изложены в Руководстве по технической эксплуатации (РЭ). ТК НЕ ДОЛЖНА дублировать все меры безопасности — иначе технология перегружается. ТК ДОЛЖНА: (а) содержать ссылки на соответствующие пункты мер безопасности РЭ в зависимости от систем, на которых проводится работа; (б) содержать в тексте операций ключевые маркеры безопасности в местах выполнения критических действий.

Исходные данные:

- Системы, на которых ведётся работа: {{systems}}
- Критические действия (из анализа ТК): {{critical_actions_json}}
- Записи базы мер безопасности, относящиеся к затронутым системам (id — номер пункта РЭ; markers — ключевые маркеры: обесточить, заземлить, стравить давление, заблокировать, зашвартовать, поставить колодки и т. п.):

{{safety_records_json}}

Виды проверок рубрики Р-3:

1. **Наличие ссылок на РЭ.** Для каждой затронутой системы ТК должна ссылаться на соответствующие пункты мер безопасности из базы (поле `doc_refs` шагов или раздел условий выполнения). Отсутствие ссылки — замечание (severity: major); `quote` = null, `quote_missing` = true; в `justification` укажи id пункта базы.
2. **Ссылки на нерелевантные пункты.** Ссылка на пункт мер безопасности, не относящийся к выполняемой работе, — замечание (severity: minor).
3. **Ключевые маркеры.** Перед критическими действиями в тексте операций должны присутствовать соответствующие ключевые маркеры из записей базы (например, «обесточить» до работ в электросети, «стравить давление» до разгерметизации гидросистемы). ОТСУТСТВИЕ обязательного маркера — замечание с severity: critical; `quote` = null, `quote_missing` = true; в `step` укажи шаг критического действия, в `justification` — id пункта базы и недостающий маркер.
4. **Позиция маркера.** Маркер присутствует, но стоит ПОСЛЕ операции, безопасность которой обеспечивает, — замечание (severity: critical); `quote` — дословная цитата шага с маркером.
5. **Перегруженность.** ТК дословно (или почти дословно) дублирует объёмные формулировки мер безопасности, которые достаточно указать ссылкой на пункт РЭ, — замечание (severity: recommendation) с рекомендацией заменить дублирование ссылкой; `quote` — дословная цитата начала дублируемого фрагмента из ТК.

Правила формирования замечаний:

- `rubric` — всегда "safety".
- `quote` — только ДОСЛОВНЫЕ цитаты из текста ТК (не из базы мер!); для замечаний об отсутствии — `quote` = null, `quote_missing` = true.
- В `justification` обязательно ссылайся на id записи базы мер безопасности (например, «РЭ п. 2.4»).
- Не выдумывай замечания: если требование выполнено, замечание не формируется.

Ответ — строго один JSON-объект вида:

{
  "findings": [
    {"rubric": "safety", "severity": "critical|major|minor|recommendation", "step": "номер шага или null", "quote": "дословная цитата или null", "quote_missing": false, "finding": "строка", "justification": "строка или null", "recommendation": "строка"}
  ]
}
